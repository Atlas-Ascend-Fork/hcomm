## 1. 分层阅读视角

按层深入，顺序阅读源文件：

1. **接口定义层**：头文件（公开头与模块内部头都属本层），理解接口签名、参数、返回值；
2. **实现层**：`.cc`/`.cpp` 实现文件，理解核心逻辑和调用链；
3. **调用链层**：从主入口追踪到叶子函数，记录每一跳的代码位置（`文件名:行号`）；
4. **核心组件层**：识别关键类，理解职责、成员变量、方法；
5. **关键特性层**：识别版本兼容、资源管理、错误处理、性能优化、并发控制、配置管理；
6. **数据结构层**：分析核心数据结构的字段、初始化方式、传递路径、生命周期。

规模阈值参考（可观测，对人与 agent 同样可执行）：源文件多于 30 个时按子目录分批推进（每批独立走完 Step 1~2，产出前再合并清单）；文件数不多但单个文件超长时同样分批（见"阅读技巧"的大文件分级）。人类作者的时间估算参考：探查阶段约 20~35 分钟（目录探索 5 分钟 + 文件阅读 15~30 分钟），结构阶段 10~15 分钟——仅供人类参考，agent 按文件数等可观测阈值执行，不感知墙钟时间。

## 2. 阅读技巧

- **先头文件后实现**：头文件定义接口契约，实现文件优先读核心方法；**核心流程涉及的方法及其错误/异常路径必须全读并追到叶子**，仅非核心辅助方法（getter/setter、纯工具函数）可选择性阅读，并记录取舍——module-doc.md Step 1.1 的全量声明（每个 .h/.cc 的类声明与方法签名）不被本技巧窄化。
- **大文件分级**：超过 500 行的文件先读头文件了解接口，再选择性阅读关键实现；超过 1000 行的文件分批读取（offset + limit），按函数边界切批。
- **并行读取**：同批无依赖的文件并行读取；`#include` 依赖关系明确后再串行追依赖。
- **关注全局状态**：全局变量、静态成员、回调注册表是理解模块行为的关键。
- **追踪跨模块引用**：`#include` 和前向声明揭示模块间依赖。
- **追踪外部接口的实现**：公开头文件中声明的接口，实现可能在适配层或其他目录，需跨目录追踪到真实实现处。
- **记录要点**：每个文件记录核心类、公开接口、关键私有方法、全局变量/回调；代码位置统一 `文件名:行号` 格式。

## 3. 四类分析技术

- **函数调用追踪**：从入口函数出发，逐层追踪被调用函数，记录每一跳的代码位置（`文件名:行号`），形成完整调用链。
- **控制流分析**：识别 if/else、switch/case、早期返回、循环条件、错误处理路径，文档化每个分支的条件和路径。
- **数据流分析**：对关键变量追踪"在哪里定义 → 在哪里修改 → 在哪里使用 → 如何在函数间流动"。
- **宏/常量分析**：识别关键的宏定义（如错误检查宏 `CHK_RET`、资源分配宏 `NEW_NOTHROW`），理解宏展开后的实际行为——宏隐藏的复杂性不许漏；关键常量：grep 常量定义与引用点，记录取值、单位和适用场景（如 `MAX_MODULE_DEVICE_NUM_V2 = 65`、超时常量、错误码枚举）。

## 4. 外部组件边界识别

探查阶段判定"本模块依赖哪些外部组件"，两条识别路径：

1. **adapter 头文件**：`#include "*_adapter_xxx.h"` / `#include "adapter_xxx.h"` 通常表示对 xxx 组件的适配层（如 `orion_adapter_hccp.h` → hccp 组件，`adapter_rts_common.h` → rts 组件）；组件名需结合 `#include` 与实现确认——adapter 也可能包装仓内/legacy 组件，不必然对应文件名中的 xxx。
2. **dlsym 动态调用**：`Hccl::DlHalFunctionV2::GetInstance().dlHalXxx` 模式经 dlsym 动态调用外部组件，最终调用 `halXxx` 函数，组件名取 `hal` 前缀对应的组件（如 `dlHalEschedSubmitEvent` → hal 组件）。

识别出的组件在交互图/类图/时序图中的画法（必须入图、指向组件的箭头）见 mermaid-guide.md 与 writing-rules.md，本节不重复。

## 5. 模块模式（关注点清单）

按模块主导模式选用关注点，复合型模块（如通信+DFX）取多张清单的并集；不属于任何模式时按通用清单（生命周期/并发/错误处理/配置/状态机）兜底复查：

| 模式 | 关注点 |
|------|--------|
| DFX/诊断 | 异常检测机制（回调注册、轮询检测、寄存器读取）；错误信息传播路径（跨环境、跨模块、上报监控）；防护机制（防重复上报、防刷屏、防并发冲突）；错误码体系和转换规则 |
| 资源管理 | 资源生命周期（创建、注册、使用、注销、释放）；资源映射关系（ID→Handle、Handle→对象）；并发安全（锁、原子操作、读写锁）；资源上限和溢出处理 |
| 通信/传输 | 通信协议和消息格式；通道建立和销毁流程；数据搬移路径和地址转换；超时和重试机制 |
| 算法/计算 | 算法策略选择逻辑；数据分片和并行度；中间结果管理；精度和性能权衡 |
| 管理/配置/拓扑/编排 | 配置加载、校验与生效流程；状态机与模式切换；并发与锁保护；错误处理与降级；拓扑/成员变更流程 |

## 6. 常见陷阱（探查阶段高发）

| 陷阱 | 后果 | 规避方法 |
|------|------|----------|
| 只追踪快乐路径 | 遗漏错误处理流程 | 追踪所有分支包括错误路径 |
| 忽略宏展开 | 宏隐藏复杂性被遗漏 | 理解宏展开后的实际行为 |
| 假设单一执行模式 | 忽略多模式/多环境差异 | 显式确认并文档化所有执行模式与侧别差异 |
| 缺少数据生命周期 | 内存管理不清楚 | 追踪分配、传递、释放完整链路 |
| 漏识别分发模式 | 流程梳理缺主干 | switch/case、函数表（HANDLER_MAP）、虚函数多态是常见分发机制，逐个识别 |
| 调用发起者与代码不一致 | 流程图方向错误 | 箭头发起者必须与代码一致：回调注册触发的函数不是调用方主动调用，不能用调用方作为发起者 |
